Section 3

Interface

The portfolio is a single long page with eight named sections: About, Academics, Experience, Projects, Simulators, Skills, Blogs, and Contact. Project case studies and blog posts open in focused dialogs, keeping the user on the same URL at all times.

Design Principles Applied

Unity Emphasis Contrast Rhythm Ordered Grid
  • Unity — one font family (Inter), one accent colour throughout.
  • Emphasis — bold section titles, lighter body text, accent on key numbers.
  • Contrast — dark text on lighter backgrounds (both modes pass WCAG AA).
  • Rhythm — identical card layout for every project and blog post.
  • Ordered Grid — a single-column reading spine; grids only appear inside cards.
Section 4

HCI Guidelines I Used

Shneiderman's Eight Golden Rules

RuleHow I used it
Strive for consistencyProjects and posts share the same card layout; every case study dialog follows the same three-section structure (Problem → Approach → Results).
Cater to universal usabilityKeyboard shortcuts for experienced users; plain links and buttons for everyone else. Dark mode and adjustable text size available.
Offer informative feedbackA toast notification appears after copying the email or switching theme with T. The active section is underlined in the sticky nav.
Design dialogs to yield closure"Email address copied." tells the user the task is definitively done.
Prevent errorsSettings expose only fixed valid choices; no free-text input fields exist on this page.
Permit easy reversal of actionsEsc closes any open overlay; pressing T again undoes the theme switch.
Support internal locus of controlNothing moves or auto-plays without user initiation; animations can be disabled via the settings panel.
Reduce short-term memory loadKey results are visible on each card row without clicking; keyboard shortcuts are listed in the footer.

Norman's Seven Principles

PrincipleHow I used it
Knowledge in the world & in the headVisible links for casual visitors; keyboard shortcuts for returning users who remember them.
Simplify task structuresEvery benchmark task completes in three steps or fewer.
Make things visibleThe sticky menu is always on screen; card rows and buttons are visually afforded as clickable.
Get the mapping rightPrevious and Next sit left and right — matching the ← / → keys; menu items 1–4 map to the first four sections.
Exploit constraintsOnly one dialog can be open at a time — clicking another project closes the first.
Design for errorIf clipboard access fails, the email is selected in the DOM and the toast explains how to copy it manually.
StandardiseConventional layout: name top-left, navigation top-right, footer at the bottom — matching web conventions users already know.

Nielsen's Ten Heuristics

HeuristicHow I used it
Visibility of system statusA thin scroll-progress line at the top of the page; a reading-progress bar inside blog-post dialogs.
Match with the real worldPlain labels such as "Copy email" and "Read case study" — no jargon.
User control and freedomEsc, a visible close button, or clicking outside all close overlays; theme switch can be undone.
Consistency and standardsIdentical card layout everywhere; standard button and dialog patterns.
Error preventionNo user-editable forms; settings are presented as fixed choices, not free input.
Recognition rather than recallProject metrics are visible on each card row without opening anything; the command palette shows matches as you type.
Flexibility and efficiency of use/ opens search; keys 1–4 jump to sections; T toggles theme; arrow keys navigate inside dialogs.
Aesthetic and minimalist designOne column, three featured projects, four blog posts — detail appears only on demand inside dialogs.
Help users recover from errorsA search with zero results suggests alternate terms and offers to browse all sections.
Help and documentation? opens the full keyboard-shortcuts reference panel.

Checking it with Models

Keystroke-Level Model (KLM)

Operator times: K (keystroke) = 0.28 s  ·  P (pointer move) = 1.10 s  ·  B (button click) = 0.20 s  ·  M (mental prepare) = 1.35 s
TaskMouse sequenceMouse timeKeyboard sequenceKey time
T1 M P B (click Projects — answer is on the row) 2.65 s M K (press 2) 1.63 s
T2 3 × (M P B) — open Blogs, open post, click Next 7.95 s M 7K M K 4.94 s
T3 2 × (M P B) — open header, click theme icon 5.30 s M K (press T) 1.63 s
T4 2 × (M P B) — scroll to Contact, click Copy 5.30 s M 6K 3.03 s
Shortcuts cut the time for every task by 38–69%.
No task requires opening a project dialog to find its answer.

Fitts' Law

ID = log2(D / W + 1). A plain 20 px text link 300 px away scores 4.0 bits. A full-width 150 px project card row at the same distance scores only 1.58 bits.

Consequence: the entire card row is a click target (not just the button inside it), and all interactive buttons are at least 44 px tall to minimise index-of-difficulty.

Hick–Hyman Law

T = k · log2(N). Four primary navigation items cost 2.0 bits of decision time. Expanding to seven items would cost 2.81 bits — roughly 40% more time to select.

This directly drove the limits: four sticky nav sections, three featured projects, four blog posts. Filter chips inside sections allow progressive disclosure without crowding the top-level menu.

Section 6

Norman's Model of Interaction

Norman's model frames interaction around two gulfs: the gulf of execution (does the user know what to do?) and the gulf of evaluation (does the user know whether it worked?). All four benchmark tasks were checked against both.

T1 — Find the test request count

Gulf of Execution

The Projects section is linked from the sticky nav. The metric is printed directly on the project card row — no dialog needed.

Gulf of Evaluation

The number is visible immediately in the card; no ambiguity about whether it has loaded.

T2 — Read a blog post, then the next

Gulf of Execution

Blog link in the sticky nav. Each card has a labelled "Read article" button. The reader shows a Next button with the next post's title visible.

Gulf of Evaluation

The dialog opens with the post title in a large heading. The title changes when Next is clicked, confirming navigation.

T3 — Change the colour theme

Gulf of Execution

A sun/moon icon button sits in the header. The T shortcut is listed in the shortcuts panel (?).

Gulf of Evaluation

Colours change instantly across the whole page. Using the keyboard shortcut also triggers a toast: "Dark theme on."

T4 — Copy the email address

Gulf of Execution

Contact link in the nav. A clearly labelled "📋 Copy Email" button sits beside the email address in the Contact section.

Gulf of Evaluation

A toast notification reads "Email address copied to clipboard!" immediately after the action.

Section 7

Conclusion

The portfolio follows the three sets of guidelines taught in the course. The formal models (KLM, Fitts' Law, Hick-Hyman) provide quantitative backing for the core design decisions: few top-level choices to minimise decision time, large click targets to reduce pointing effort, key information visible on each card row so no dialog needs to be opened for a quick lookup, and keyboard shortcuts up to 69% faster for frequent users.

Keeping the interface minimal was the single most deliberate decision. Every element that did not directly serve one of the four benchmark tasks — or reduce cognitive load for a target user persona — was removed.

Summary: a single-page portfolio that is effective (tasks complete in ≤ 3 steps), efficient (shortcuts cut time by up to 69%), error-free (no forms, guided actions, clear reversals), easy (conventional layout, visible affordances), and enjoyable (polished dark/light theme with smooth micro-animations).
